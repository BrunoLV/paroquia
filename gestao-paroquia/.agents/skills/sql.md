# Skill do Agente de IA: Escrita de SQL e Modelagem Relacional (Especialista Multi-Dialeto)

## 1. Visão Geral e Contexto
Esta skill capacita o Agente de IA a gerar, revisar, otimizar e refatorar consultas SQL e estruturas DDL (Data Definition Language) de forma autônoma. O agente deve garantir que todo código produzido siga padrões rigorosos de legibilidade, desempenho, segurança e boas práticas de modelagem relacional, adaptando a sintaxe dinamicamente entre o padrão ANSI SQL e as particularidades do PostgreSQL, MySQL e H2.

## 2. Diretrizes de Escrita e Formatação SQL
O Agente deve gerar código SQL limpo e padronizado:
*   **Caixa Alta para Palavras-Chave:** Instruções nativas do SQL devem ser escritas estritamente em maiúsculo (ex: `SELECT`, `FROM`, `WHERE`, `JOIN`, `GROUP BY`, `ORDER BY`).
*   **Identificadores em Caixa Baixa:** Nomes de tabelas, colunas, views e schemas devem ser escritos em minúsculo, utilizando `snake_case` para separação de palavras (ex: `usuario_id`, `data_cadastro`).
*   **Uso de Aliases:** Sempre utilize aliases explícitos e significativos ao realizar junções (joins), qualificando todas as colunas para evitar ambiguidades (ex: `SELECT u.nome, p.preco FROM usuario u JOIN pedido p ON u.id = p.usuario_id`).
*   **Evitar SELECT *:** Sempre liste explicitamente as colunas necessárias nas consultas de produção. O uso de `SELECT *` é estritamente proibido para evitar overhead de rede e quebras de contrato em alterações de schema.

## 3. Princípios de Desempenho e Otimização
Ao estruturar queries e schemas, o Agente deve focar na eficiência do banco de dados:
*   **Estratégia de Índices:** Crie índices (`INDEX`) explicitamente para colunas frequentemente utilizadas in cláusulas `WHERE`, `JOIN` ou `ORDER BY`. Evite indexar colunas com baixa cardinalidade (ex: colunas booleanas).
*   **Sargabilidade (Sargable Queries):** Escreva cláusulas `WHERE` que permitam o uso eficiente de índices. Evite aplicar funções ou operações diretamente nas colunas indexadas (ex: use `data_criacao >= '2026-01-01'` em vez de `EXTRACT(YEAR FROM data_criacao) = 2026`).
*   **Evitar Subqueries Correlacionadas:** Dê preferência ao uso de `JOIN` ou expressões de tabela comuns (CTEs - `WITH`) em vez de subqueries que executam linha por linha, reduzindo a complexidade de tempo da execução.

## 4. Segurança e Integridade dos Dados
O Agente deve blindar o banco de dados contra falhas de segurança e inconsistências:
*   **Prevenção contra SQL Injection:** O agente deve projetar estruturas que incentivem o uso de *Prepared Statements* e consultas parametrizadas. Nunca concatene inputs dinâmicos diretamente em strings SQL.
*   **Restrições de Integridade (Constraints):** Defina explicitamente chaves primárias (`PRIMARY KEY`), chaves estrangeiras (`FOREIGN KEY`), restrições de unicidade (`UNIQUE`) e regras de obrigatoriedade (`NOT NULL`) para garantir a consistência dos dados ao nível do motor do banco.

## 5. Matriz de Compatibilidade e Dialetos (Blueprints)
O agente deve adaptar a geração de scripts DDL/DML com base no dialeto alvo especificado pelo harness.

### A. Tipagem Numérica Exata (Valores Monetários)
*   **ANSI / PostgreSQL / MySQL / H2:** Use estritamente `NUMERIC(p,s)` ou `DECIMAL(p,s)`. O uso de `FLOAT` ou `DOUBLE` para dados financeiros é terminantemente proibido.

### B. Auto-Incremento e Chaves Primárias (DDL)
Ao criar colunas identificadoras auto-incrementais, utilize a sintaxe correta por engine:
*   **ANSI SQL:** `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
*   **PostgreSQL:** `id BIGSERIAL PRIMARY KEY` (ou padrão ANSI)
*   **MySQL:** `id BIGINT AUTO_INCREMENT PRIMARY KEY`
*   **H2 Database:** `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` (ou modo de compatibilidade `AUTO_INCREMENT`)

#### Exemplo Comparativo DDL (PostgreSQL vs MySQL vs H2)

```sql
-- [POSTGRESQL]
CREATE TABLE cliente (
    id BIGSERIAL PRIMARY KEY,
    nome VARCHAR(150) NOT NULL,
    criado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- [MYSQL]
CREATE TABLE cliente (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(150) NOT NULL,
    criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- [H2 DATABASE]
CREATE TABLE cliente (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(150) NOT NULL,
    criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

```

### C. Limitação de Resultados e Paginação (DML)

Ao paginar ou limitar registros retornados, aplique a palavra-chave apropriada:

* **ANSI SQL / PostgreSQL / H2:** `LIMIT 10 OFFSET 0` (ou padrão ANSI: `FETCH FIRST 10 ROWS ONLY`)
* **MySQL:** `LIMIT 0, 10` ou `LIMIT 10 OFFSET 0`

### D. Upsert (Inserir ou Atualizar em Conflito)

Ao lidar com persistência idempotente onde a chave pode já existir:

* **PostgreSQL / H2 (v2+):** `INSERT INTO ... ON CONFLICT (coluna) DO UPDATE SET ...`
* **MySQL:** `INSERT INTO ... ON DUPLICATE KEY UPDATE ...`

#### Exemplo Comparativo Upsert (PostgreSQL vs MySQL)

```sql
-- [POSTGRESQL]
INSERT INTO configuracao (chave, valor) 
VALUES ('timeout', '30') 
ON CONFLICT (chave) DO UPDATE SET valor = EXCLUDED.valor;

-- [MYSQL]
INSERT INTO configuracao (chave, valor) 
VALUES ('timeout', '30') 
ON DUPLICATE KEY UPDATE valor = VALUES(valor);

```

## 6. Checklist de Revisão e Anti-Patterns a Evitar

Antes de finalizar qualquer entrega de script SQL, o Agente deve validar:

* **Falta de Chaves Estrangeiras:** Existem tabelas relacionadas sem a definição explícita de `FOREIGN KEY`? *(Se sim, adicione-as imediatamente para garantir integridade referencial)*.
* **Filtros Não Sargáveis:** A cláusula `WHERE` utiliza funções como `LOWER()` ou operações matemáticas na coluna indexada? *(Refatore para que a coluna fique isolada de um lado do operador)*.
* **Junções Implícitas:** O script faz uso de `FROM tabela_a, tabela_b WHERE tabela_a.id = tabela_b.a_id`? *(Refatore utilizando a sintaxe explícita `JOIN ... ON ...`)*.
* **Conflito de Dialeto no H2:** Se o ambiente de teste usa H2 para simular PostgreSQL/MySQL, garanta que funções nativas específicas (como `NOW()` do MySQL ou `ILIKE` do Postgres) não quebrem o H2, preferindo sintaxes ANSI (`CURRENT_TIMESTAMP`, `LOWER(col) LIKE`).
